مشروع Firebase: `maqdi-19689` — المنطقة: `europe-west3`

```
maqdi/
├── core/            وحدة أندرويد مشتركة: النماذج، الاتصال بالخادم، الدخول بـ Google، الواجهة العربية RTL
├── app-customer/    تطبيق «مقضي» للزبائن          (com.maqdi.customer)
├── app-partner/     تطبيق «مقضي للشركاء»          (com.maqdi.partner)
```

## خطوات التشغيل بالترتيب

### 1) الأسرار (مرة واحدة)
GitHub ← Settings ← Secrets and variables ← Actions ← New secret:
`FIREBASE_SERVICE_ACCOUNT` = كل محتوى ملف JSON لحساب الخدمة (من Firebase ← Project settings ← Service accounts).
لا ترسله لأحد ولا ترفعه إلى المستودع.

### 2) نشر الخلفية
Actions ← **Firebase Deploy** ← Run workflow.
إن ظهر خطأ «API not enabled» فعّل الخدمة المذكورة من الرابط الظاهر في الخطأ ثم أعد التشغيل.
إن ظهر PERMISSION_DENIED امنح حساب الخدمة (من Google Cloud Console ← IAM) الأدوار:
`Cloud Functions Admin`, `Service Account User`, `Cloud Scheduler Admin`, `Artifact Registry Writer`, `Cloud Build Editor`, `Firebase Rules Admin`, `Cloud Datastore Index Admin`.

### 3) تسجيل التطبيقين في Firebase (ضروري لتسجيل Google)
Firebase ← Project settings ← Add app ← Android، مرتين:

| التطبيق | Package name | SHA-1 |
|---|---|---|
| الزبون | `com.maqdi.customer` | `9E:46:BD:F3:C6:A5:E2:C0:3A:91:BB:45:B5:20:C2:0F:0A:02:D3:F7` |
| الشركاء | `com.maqdi.partner` | نفس البصمة |

**مهم:** فعّل مزوّد Google في Authentication وأضف بصمة SHA-1 **قبل** تنزيل `google-services.json`، وإن أضفتها بعده فأعد تنزيله، وإلا يفشل تسجيل الدخول.
ثم نزّل `google-services.json` لكل تطبيق وضعه هنا:
- `app-customer/google-services.json`
- `app-partner/google-services.json`

بصمة SHA-1 أعلاه تخص مفتاح `keystore/debug.keystore` المرفق، وهو مفتاح تصحيح مشترك وغير سري عمدًا، حتى تبقى البصمة ثابتة في كل بناء على GitHub. للإطلاق النهائي ننشئ مفتاحًا سريًا آخر.

### 4) بناء التطبيقين
Actions ← **Android Build** ← Run workflow. عند النجاح تجد ملفي APK في قسم Artifacts أسفل صفحة التشغيل. نزّلهما وثبّتهما على الهاتف.

### 5) أول مدير
في Firestore Console أنشئ مجموعة `invites` ووثيقة معرّفها بريدك على Gmail **بأحرف صغيرة** وفيها:
`role` = `admin` (نص) و`used` = `false` (منطقي).
ثم سجّل الدخول بهذا البريد في **مقضي للشركاء**.

### 6) تهيئة المتاجر
من تطبيق الشركاء (مدير) ← الإدارة ← المتاجر ← أضف المتجر ← «دعوة تاجر» ببريده ← ثم أضف المنتجات.
والتاجر يسجّل الدخول ببريده في تطبيق الشركاء.

## الميزات المضافة في التحديث الأخير
- فلترة كل الطلبات في الإدارة حسب الحالة والمتجر والتاريخ.
- ملخص مالي لأي فترة (إيراد التوصيل، المصروفات، الصافي، حركة النقد).
- تصنيف المنتجات وتصفيتها عند الزبون.
- شريط يظهر عند انقطاع الإنترنت. أيقونة للتطبيقين.

## ما اختُبر وما لم يُختبر
- **اختُبر:** 8 اختبارات لآلة حالات الطلب (تعمل داخل Firebase Deploy قبل النشر).
- **كُتبت ولم تُشغَّل بعد:** 11 اختبارًا لقواعد الأمان (`rules-tests/`) تعمل بمحاكي Firebase عبر Actions ← **Rules Tests**. شغّلها قبل أي إطلاق؛ فشل أي اختبار يعني ثغرة أو خطأ في القواعد.
- **لم يُبنَ ولم يُشغَّل بعد:** كود Cloud Functions وكود أندرويد كتبتُه دون إمكانية بنائه هنا (بيئتي بلا إنترنت)، فأول بناء على GitHub قد يُظهر أخطاء ترجمة. أرسل لي السطور الحمراء من سجل Actions وأصلحها.
- **لم تُختبر:** قواعد الأمان على المحاكي، ولا الاتصال الضعيف، ولا اختبارات القبول الأربعة عشر على جهاز حقيقي. لا تعتمد المشروع للإنتاج قبل تنفيذها (انظر أدناه).

## قبل الإطلاق الفعلي
1. نفّذ اختبارات القبول الـ14 يدويًا على هاتفين (زبون وتاجر) ببيانات تجريبية.
2. فعّل App Check وضع حدًّا لمعدل الطلبات.
3. أنشئ مفتاح توقيع سريًا للإصدار النهائي.
4. احذف الطلبات التجريبية (علامة «تجريبي») من لوحة Firestore قبل الإطلاق.
5. إيراد التوصيل = رسوم التوصيل − الخصم. مستحق المتجر ≠ ربح المنصة.

## قرارات اتُّخذت (قابلة للتغيير)
- التحصيل: **الموصّل يستلم المبلغ كاملًا ثم يسوّي مع المتاجر** (الخيار أ).
- تعذّر التسليم: تعود البضاعة للمتجر بلا قيود مالية، والاستثناءات بقيد تصحيح.
- الإلغاء: الزبون قبل التجهيز؛ التاجر في «تمت الموافقة» و«قيد التجهيز»؛ المدير قبل التوصيل.
- المخزون يُدار يدويًا من التاجر. الأدوية بوصفة طبية غير مدعومة. الخصم محجوز في البنية (0 حاليًا).
- الإشعارات تعمل عبر FCM (طلب جديد، موافقة، جاهز للاستلام، في الطريق، تم التسليم...).
