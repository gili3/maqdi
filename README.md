# مقضي — منصة توصيل محلية (الدفعة 1: أربع واجهات + خادم أقوى)

مشروع Firebase: `maqdi-19689` — المنطقة: `europe-west3`

## الواجهات الأربع (أربعة تطبيقات APK مستقلة بخلفية واحدة)

| التطبيق | الحزمة | الدور المسموح | ما يفعله |
|---|---|---|---|
| مقضي | `com.maqdi.customer` | زبون | التصفح، السلة، الطلب، الموافقة على الإجمالي، التتبع |
| مقضي للمتاجر | `com.maqdi.merchant` | تاجر | مراجعة الطلبات وتعديلها، التجهيز، المنتجات والمخزون، حساب المتجر |
| مقضي للمندوبين | `com.maqdi.courier` | مندوب | الطلبات الجاهزة، الاستلام والتسليم والتحصيل، سجل توصيلاته |
| مقضي للإدارة | `com.maqdi.admin` | مدير | اللوحة، كل الطلبات، المتاجر، المستخدمون، المالية، الإعدادات، التدقيق (والمدير يوصّل من تبويب التوصيل) |

كل تطبيق يرفض تلقائيًا أي حساب دوره غير دوره. والصلاحيات الحقيقية تُفرض في الخادم وقواعد Firestore لا في الواجهة.

```
core/               وحدة مشتركة: النماذج، الاتصال، الدخول بـ Google، السمة، الإشعارات
features-partner/   شاشات المتجر والمندوب والإدارة (تستعملها التطبيقات الثلاثة)
app-customer/ app-merchant/ app-courier/ app-admin/   أربعة تطبيقات رقيقة
functions/          Cloud Functions (TypeScript)
rules-tests/        اختبارات قواعد الأمان
google-services.json   ملف Firebase الواحد للتطبيقات الأربعة (في جذر المستودع)
```

## ما الجديد في هذه الدفعة
**الخادم والأمان**
- إصلاح خطأ: مندوب ثانٍ يضغط «استلمت» بعد أن استلمه غيره كان يتلقى نجاحًا كاذبًا. صار يتلقى `already_taken`.
- سقف الطلبات المفتوحة لكل زبون (افتراضي 3، يُعدَّل من إعدادات الإدارة) لمنع الإساءة.
- مركز إشعارات داخل التطبيق + إشعارات الدفع، تصل للجهة الصحيحة في كل حالة (زبون، متجر، مندوب، إدارة).
- حقول بحث على المنتجات (اسم مطبَّع واسم المتجر) تمهيدًا للبحث العام.
- تقارير من الخادم: `adminReport` و`merchantReport` و`courierReport` (حسب اليوم والمتجر وأكثر المنتجات مبيعًا).
- قواعد وفهارس جديدة للإشعارات والتقارير وسجل المندوب.

**التطبيقات**
- أربعة تطبيقات مستقلة بدل اثنين، بجرس إشعارات وشارة غير مقروء في كل واحد.
- شاشة «سجلي» للمندوب بملخص المبالغ التي حصّلها.
- حقل سقف الطلبات في إعدادات الإدارة.

**الدفعة 2 (كُتبت، بانتظار أول بناء — انظر STATUS.md):** نظام تصميم موحّد، بحث عام للزبون، شاشات تقارير. **المتبقي منها:** نظام تصميم موحّد وشاشات احترافية، البحث العام في واجهة الزبون، شاشات التقارير في الإدارة والمتجر والمندوب، تحسينات الأداء (تحميل تدريجي وتخزين الصور)، واختبارات إضافية.

## خطوات التشغيل بعد هذه الدفعة
1. **سجّل ثلاثة تطبيقات جديدة** في Firebase ← Project settings ← Add app ← Android، بالبصمة نفسها `9E:46:BD:F3:C6:A5:E2:C0:3A:91:BB:45:B5:20:C2:0F:0A:02:D3:F7`:
   `com.maqdi.merchant` و`com.maqdi.courier` و`com.maqdi.admin`
   (تطبيق الزبون `com.maqdi.customer` مسجّل من قبل. و`com.maqdi.partner` القديم لم يعد مستعملًا.)
2. نزّل `google-services.json` **من جديد** (يحوي كل التطبيقات المسجّلة) واستبدل به الملف في **جذر** المستودع. لم يعد هناك ملف لكل تطبيق، فملف البناء ينسخه للتطبيقات الأربعة ويتحقق أن كل حزمة مسجّلة.
3. شغّل بالترتيب: **Firebase Deploy**، ثم **Rules Tests**، ثم **Android Build**.
4. ينتج البناء أربعة ملفات APK في Artifacts.
5. الحسابات: المدير الأول من وثيقة `invites` (كما في السابق)، ثم من تطبيق الإدارة: ادعُ التجار من شاشة المتجر، والمندوبين من شاشة المستخدمين.

## ما اختُبر وما لم يُختبر
- **اختُبر فعلًا (21 اختبارًا):** آلة الحالات، منطق التقارير، تطبيع البحث العربي، خطة الإشعارات، وحراس تغيير حالة الطلب (منع الاستلام مرتين، منع التجهيز قبل الموافقة، منع حركة المندوب قبل الجاهزية، منع الإغلاق مرتين). التفاصيل في `STATUS.md`.
- **كُتب ولم يُشغَّل:** 13 اختبارًا لقواعد الأمان (تعمل في Rules Tests).
- **لم يُبنَ بعد:** كود Cloud Functions وأندرويد الجديد. أول بناء على GitHub قد يُظهر أخطاء ترجمة، فأرسل لي السطور الحمراء.
- لا يُطلَق للناس قبل تنفيذ اختبارات القبول الأربعة عشر يدويًا على هاتفين.

## قواعد التشغيل (لم تتغير)
- لا تجهيز قبل موافقة الزبون الصريحة على الإجمالي النهائي.
- لا حركة للمندوب قبل `ready_for_pickup`، ولا تسليم قبل `out_for_delivery`.
- لا طلب مكرر عند انقطاع الاتصال (معرّف إرسال ثابت)، ولا إتمام أو تحصيل مرتين.
- القيود المالية لا تُعدَّل ولا تُحذف، والتصحيح بقيد مرتبط بالأصل.
- مستحقات المتاجر منفصلة عن إيراد التوصيل، والتحصيل بالخيار أ (المندوب يستلم المبلغ كاملًا).
